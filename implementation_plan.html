Clinic Intake Dossier: Implementation Plan

Autonomous conversion of public clinic websites into structured onboarding dossiers, verifier-checked evidence quotes, requirements gap tracking (tasks.csv), and clinically conservative reel hooks.

Core Principle: "The LLM extracts; code verifies and decides what is missing."

1. Context & Operational Purpose

OneHeroAI provides managed AI twin services to doctors: weekly patient-education videos, a voice twin for clinic reception calls, and a video twin answering patient questions. Onboarding is currently stalled by scattered inputs. This tool turns one public clinic URL into an operational dossier so an onboarding coordinator starts the first call fully prepared.

Every gap becomes an owned task. Outputs per run:

  • dossier.json — Machine-readable structured intake profile with verifier metadata.
  • dossier.html — Plain, readable HTML page with color-coded chips, copy-to-clipboard WhatsApp drafts, and direct download links.
  • dossier.md — Executive markdown dossier for clinical review.
  • tasks.csv — Tracker-ready tasks for every missing requirement with owner, next action, and 2-day due dates.

2. Verified Tech Stack & SDK Checks

● Gemini via @google/genai (generateContent)

Live model query completed for your GEMINI_API_KEY: models/gemini-3.8-flash and models/gemini-3.5-flash are verified available. We use gemini-3.8-flash (configurable via GEMINI_MODEL) with client.models.generateContent, temperature: 0.1, and JSON schema converted via zodToJsonSchema. All Claude/Anthropic references removed.

ⓘ Firecrawl SDK v4.42.4 & Alexandria Verification

Verified against installed SDK types: firecrawl.map(url, { limit: 12 }) and firecrawl.scrape(url, { formats: ['markdown'] }). Alexandria search was evaluated for healthcare registries (e.g. CMS NPPES); to prevent cross-border failures and keep all facts strictly grounded in the clinic's public site, third-party registries are skipped and recorded in DEVLOG.md.

⚠ Untrusted Data Shield & Substring Verifier

System prompt treats all scraped text as untrusted data. In Step 4, a pure code verifier tests every evidence_quote (< 25 words) as an exact substring of the scraped markdown. If not found, code automatically downgrades the field to INFERRED or MISSING.

3. End-to-End Pipeline Architecture

flowchart TD A["Clinic URL Input"] --> B["Page Mapper (Firecrawl.map, Max 12 pages)"] B --> C["Filter: Same-Domain, Heuristic Scoring (Home, About, Doctor, Services, FAQ, Contact, Blog)"] C --> D["Batch Scraper (Firecrawl.scrape to Markdown, 30s timeout, char cap)"] D --> E["Gemini Extraction (generateContent with zodToJsonSchema, temp 0.1)"] E --> F["Zod Parse & 1x Self-Correction Retry"] F --> G["VERIFIER (Pure Code): Verbatim Substring Match on Markdown"] G -- "Quote missing/altered" --> G1["Downgrade to INFERRED/MISSING + Log Stats"] G -- "Quote verified" --> H["GAP ENGINE (Pure Code): Compare vs requirements.config.json"] H --> I["Deterministic Hook Linter (Reject Guarantees/Superlatives)"] I --> J["Generator: Status Header, WhatsApp Drafts, tasks.csv"] J --> K["Renderers: dossier.json, dossier.html, dossier.md, tasks.csv"]

4. Gap Engine & requirements.config.json

Requirements are defined in requirements.config.json, allowing changes without altering code. Every item is labelled "assumed, confirm with OHAI".

5. Status Header & Reel Hooks Linter

Status Header (Top of Every Dossier)

Provides instantaneous operational visibility: fields found / inferred / missing counts, verifier downgrades, blockers count, drafts ready, and ready_for_strategy status.

"7 of 13 found, 2 inferred, 4 missing, 1 verifier downgrade, 2 blockers, 4 drafts ready. Ready for strategy: false (blocked on approval contact, booking destination)"

5 Reel Hooks with Deterministic Code Linter

Each hook carries needs_clinical_review: true. A deterministic code linter rejects and regenerates hooks containing:

  • Outcome guarantees ("guarantee", "100%", "promise")
  • Painless promises ("painless", "zero pain")
  • Superlatives & cures ("best", "cure", "miracle", "#1")
  • Before / after claims or efficacy statements beyond the clinic's site
